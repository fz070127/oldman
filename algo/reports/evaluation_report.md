# 跌倒检测评测报告

## 结论摘要

可用于边缘端疑似跌倒提醒原型，真实住宅独立报警的依据仍不足。val 检出 6/6，test 仅 2/6，两个集合各有 2/8 段日常活动误报，四段均为主动躺卧。两个集合的跌倒确认数均为 0。已触发的八段在证据帧后全部不足 3 秒，另有四段测试跌倒在第一道高度骤降规则即漏检。延长录像有助于验证确认能力，无法据此修正已观测到的漏检率。

## 3. 误报分析（Q2）

| 集合 / ADL | 等级 / 首帧 | 看片动作 | 触发证据（降幅 / 躯干角 / 宽高比） |
| :--- | :--- | :--- | :--- |

val 和 test 的 ADL 各误报 2/8 段，P0 各 0 段。**人工已看片确认 adl-36、adl-37 均为先坐到床沿，再侧躺到床上。** 两段均保持床面支撑。倾斜、框变矮变宽会同时出现在正常上床和跌倒中，宽高比 1.2 的门槛无法排除该动作。家具 ROI 默认为空。可在校准过的床区域检验降级策略，同时单独复核床边真实跌落，以免把两类事件一起抑制。

**延长 3 秒的条件推算。** 假设片尾最后一帧的人体框、位置、姿态和漏检状态原样延续 90 帧，沿用原 P1 轨迹和既有运动历史，在规定确认时刻判断。由此推算已有 P1 可升级 train 12、val 2、test 0，共 14 段。val 对应 fall-05、fall-29。此数是冻结画面的反事实情景；真实人在后续可能移动、恢复或重新被摄像头看见，实际升级数没有观测值。

test 的 fall-09 已产生 0.528 个框对角线的位移，超过 0.30。fall-01 已移动 0.334，最后可见轨迹在第 158 帧，片段到第 160 帧。两段即使在该假设下补足长度，也无法通过确认。因此短片裁切足以解释当次缺少完整窗口，持续跟踪和位移门槛仍独立影响确认。各段的 `extension` 提供末帧可见性、观察框数、投影覆盖率、运动量、终点姿态和推算结果。

| 集合 | 启用兜底 | 关闭兜底 | 净新增 | 检出率差 |
| :--- | :--- | :--- | :--- | :--- |
| val | 6/6（100%） | 4/6（66.7%） | 2 段 | 33.3 个百分点 |
| test | 2/6（33.3%） | 2/6（33.3%） | 0 段 | 0 个百分点 |

val 的 fall-19、fall-25 完全依赖框兜底。fall-03 在第 187 帧由框兜底首报，关闭后主路径在第 190 帧首报。直接删除已有 JSON 中的框事件会把净贡献高估为三段。

配对时仅在内存中将框降幅门槛置为 1，以禁用 B 分支。对有 B 触发条件的跌倒段运行消融，逐段保存 `no_bbox_first_frame`。其余段通过逐轨迹特征确认 B 的完整触发条件在任何一帧均不成立，直接沿用原判定。test 只对 fall-01、fall-09 做了关闭 B 的额外回放，另四段均无 B 候选。冻结测试指标始终取自原始文件。

## 7. 失败案例分析（Q6）

逐段对照 RGB 时序画面与同一人员轨迹的特征。T1 要求一秒内降幅 >0.45，且窗口内峰值之后的下降速率 >0.85 个画面高度/秒。下列速率仅统计降幅已过线的窗口。

| 测试漏检段 | 有框帧 / 总帧 | 最大降幅 | 降幅过线时最大速率 | 画面与规则归因 |
| :--- | :--- | :--- | :--- | :--- |
| fall-04 | 90/96 | 0.512 | 0.791 | 由椅旁的低姿态前扑，向画面下缘滚出；框高降幅与下降速率未同时过线。 |
| fall-08 | 91/91 | 0.386 | — | 坐姿起跌，手先撑地；坐姿到卧地的相对框高变化不足。 |
| fall-21 | 41/55 | 0.364 | — | 正对镜头前扑并越出画面下缘，最后阶段整个人体框丢失。 |
| fall-24 | 54/60 | 0.721 | 0.784 | 椅边前倾、手膝撑地，身体在下缘被裁切；有足够降幅时框高下降速率偏低。 |

四段通过 T1 的帧数均为零。fall-08 全程都有可用姿态，fall-21 则在第 43 帧后丢失人体框。fall-04、fall-24 的速率是框高代理量，受坐姿起点、投影和截边影响，不能据此认定演员的真实跌倒速度慢。逐轨迹门槛计数见 `sequences[].gates`。[四段漏检画面](../data/processed/a4-review/miss.jpg)

## 8. 已知边界与局限

固定机位、单房间、以单个目标为主，fall-13 画面中另有旁观者。年轻演员模拟动作，无法据此估计独居老人真实跌倒的检出率。剪辑缺少确认所需的长时间静止，没有真实住宅连续流、红外或系统性遮挡测试。部分视频有人体自遮挡或画面截边。ADL 分组给出的是精选动作片段中的误报比例，每户每天告警多少次需要连续运行数据。

## 9. 对 A5 边缘部署的建议

先以 P1 提醒原型部署，保留按人跟踪、框兜底、恢复站立撤销和独立的 P0 观察窗口。连续流应记录证据帧时间及实际发送时间。长时间无框时保留证据缺失状态。床面 ROI 需逐机位校准，部署前须用真实长度的跌倒与主动躺卧片段验证。

CPU 预算建议先以单路 15 fps 做原型，周期约 66.7 ms；为采集及姿态提取预留 60 ms/帧，规则计算预留 2 ms/帧，其余留给排队和输出。A2 在开发机双进程、离线批处理的平均吞吐为 44.68 ms/帧，冻结 test 规则引擎含缓存读取最慢 25.57 ms/**段**。这两项均不能替代目标板单路持续运行的延迟、温升和丢帧实测。降低采样率时按实际时间戳计算窗口与速率，并重新验证跟踪门槛。预算和实测值见 `edge_planning`、`extraction`、`frozen_metrics.test`。
